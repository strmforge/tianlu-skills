# Public Agent Skill Mechanism Intake Review

Status: incubating

Scope: runtime-neutral intake and synthesis method

## Signal

A controller-assisted review of public agent, skill, MCP, and workflow repositories is producing useful mechanisms faster than a single agent can manually promote them. The useful unit is not the raw repository, star count, article framing, or worker summary. The useful unit is a controller-audited mechanism with source role, boundary, and placement.

This candidate records the method for turning batches of public repository review into Tianlu incubation material without installing, activating, or copying third-party behavior.

## Source Evidence

- Controller-audited local QClaw short-worker receipts from the public repository reading loop on 2026-06-24.
- Repository-level samples reviewed only through local lightweight source files such as README, SKILL.md, metadata, examples, and directory shape.
- Related Tianlu candidates:
  - `public-skill-triage-role-envelope-pilot.md`
  - `agent-role-skill-bundle-routing-review.md`
  - `agent-role-envelope-cycle-review.md`
  - `loop-engineering-workflow-review.md`
  - `context-harness-loop-readiness-review.md`

The receipts are evidence packets, not neutral law. A worker summary is accepted only after controller spot-check, path verification, and conflict correction.

## Proposed Trigger

Use this candidate when a batch of public repositories has been read for agent, skill, role, MCP, workflow, or loop patterns and the result needs to be moved from local receipts into a neutral, reviewable Tianlu surface.

Typical input:

- public skill packs;
- agent role packs;
- prompt and rule packs;
- workflow or loop frameworks;
- MCP or connector registries;
- eval, harness, routing, or memory infrastructure;
- desktop or runtime agent clients.

## Proposed Mechanism

Before writing public-repo learning into Tianlu:

1. Keep the raw receipt local.
   - Do not publish raw worker output, local account paths, provider details, token usage, hidden reasoning, or unreviewed claims.
2. Verify source anchors.
   - Check cited local paths and spot-check the strongest or conflicting claim.
3. Extract mechanisms, not repo praise.
   - Convert each accepted item into trigger, action, expected outcome, boundary, and failure mode.
4. Group by reusable surface.
   - Registry and index surfaces.
   - Role-envelope and bundled-skill surfaces.
   - Runtime, harness, gate, and event-truth surfaces.
   - Eval, evidence-ring, and rubric surfaces.
   - State, memory, isolation, and portability surfaces.
   - Scheduled monitor and alert-loop surfaces.
5. Preserve authority boundaries.
   - Source review is not install approval, runtime proof, account permission, commit authority, memory write authority, or push approval.
6. Add only neutral summaries to Tianlu.
   - Public repo names may appear as examples, but the method should remain reusable without the example.
7. Add eval or negative cases before promotion.
   - Incubator notes can collect mechanisms; promotion needs replay, conflict review, and independent oracle coverage.

## Initial Scope

- Intake and synthesis of public repository mechanisms after local controller audit.
- Incubation of repeated patterns that support Tianlu role envelopes, skill bundles, workflow contracts, and loop gates.
- Not a recommendation to install or activate any listed repository.
- Not a claim that the listed repositories' runtime behavior was executed or validated.

## Known Failure Modes

- Mechanism laundering: a worker summary becomes neutral method without controller verification.
- Repo-name worship: a famous repo or popular article is treated as evidence of local fitness.
- Runtime bleed: install instructions, scripts, credentials, schedules, hooks, or account actions leak into Tianlu as if they were approved behavior.
- Over-generalization: a single scoped repo becomes a broad law before replay evidence.
- Registry flattening: large lists are treated as one method instead of structured absorb-layer input.
- Eval theater: a repo's own eval, badge, or benchmark is treated as independent validation without checking scope and negative cases.
- Local-only leakage: controller paths, provider details, account state, token usage, or raw worker output enter neutral files.
