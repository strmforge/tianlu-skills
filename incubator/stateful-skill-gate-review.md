# Stateful Skill Gate Review

Status: incubating

Scope: runtime-neutral review method

## Signal

Controller-audited public skill and agent batches show a recurring pattern: the strongest skills are not just prompts. They carry a measurable gate, a state surface, and a bounded comparison rule. Examples include creative case-library calibration, three-axis research prompts, meta-skill optimization loops, volume-preserving editing gates, database-audit safe probes, cloud data-agent session modes, and sandbox or evolvable-context platforms.

This candidate keeps that pattern in incubation. It is not an endorsement of any source repository, install path, credential flow, cloud service, security probe, editing claim, or sandbox runtime.

Controller-audited local QClaw short-worker receipts from 2026-06-25 include source-review evidence for:

## Proposed Trigger

Use this candidate when a public skill, internal role, or agent workflow claims to improve quality through one or more of these surfaces:

- a measurable threshold, score, rubric, or pass/fail gate;
- a state file, memory bank, rolling summary, session reuse, or persisted context;
- baseline-versus-enhanced comparison;
- safe probe, rollback, canary, dry run, or reversible execution;
- domain calibration corpus, example library, or reference card set;
- sandbox, session, workspace, or isolated execution environment;
- exact fix output, transformed artifact, or structured report.

## Proposed Mechanism

Review stateful skills as gated operating loops:

1. Identify the gate.
   - Name the threshold, rubric, review condition, safe probe, baseline comparison, or acceptance test.
2. Identify the state.
   - Name the memory file, session, workspace, context layer, rolling summary, lock, sandbox, or result ledger.
3. Identify the action.
   - Name what the skill changes, generates, edits, probes, scores, or reports.
4. Identify the rollback or stop condition.
   - Revert, ask the user, downgrade claim strength, keep source-review-only, or stop before activation.
5. Separate protocol evidence from execution proof.
   - A source file can show that a protocol exists; it does not prove the protocol was run correctly.
6. Separate domain usefulness from authority.
   - Security probes, cloud data sessions, AIGC editing, persona calibration, code sandboxes, and design-tool bridges each have their own authority and harm surfaces.
7. Preserve conflicts.
   - If source files disagree about counts, scope, metrics, or validation status, carry the conflict instead of normalizing it away.
8. Add eval before promotion.
   - Replay the gate on small safe examples, compare against a single-prompt baseline, and add negative cases for fake thresholds and state laundering.

## Initial Scope

- Source-level review of stateful skill packages, gated domain workflows, and agent platforms that expose state or measurable quality claims.
- Incubator synthesis only.
- Not a runtime adapter.
- Not an install, probe, data-access, editing-service, or sandbox-activation guide.

## Known Failure Modes

- Gate theater: a threshold is named but never measured.
- State laundering: a memory file, session, or workspace is treated as permission to persist future behavior.
- Baseline theater: a with-skill output is praised without a comparable baseline.
- Probe laundering: a safe-probe description is treated as permission to touch real systems.
- Sandbox laundering: an isolated runtime claim is treated as proof of security, compliance, or execution fitness.
- Corpus laundering: case counts, quote libraries, or persona distillations are treated as truth without source and conflict review.
- Metric laundering: claimed improvement numbers are repeated without replay, denominator, or failure cases.
- Domain-action creep: a useful method in editing, security, data, design, or code execution becomes permission to use accounts, credentials, browsers, cloud services, or local runtimes.

## Verification Needed

- Replay on at least three safe examples: one prompt-method skill, one editing or content transformation skill, and one quality or security review skill.
- Compare against single-prompt baselines for output quality, evidence separation, and boundary handling.
- Add negative eval cases where a named threshold has no measurement, a state file is treated as durable memory authority, and a safe-probe description becomes real-system access.
- Decide whether this remains a supporting incubator note or becomes a productive review playbook for gated skills.
